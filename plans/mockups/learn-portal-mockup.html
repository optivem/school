Should I assert on the exception message or just the type?

Romain Chambard · Module 03 · 2 days ago
✓ Answered
When testing the validation, I'm doing assertThrows(ValidationException.class, …) — but should I also assert on the message text?
VJ
Valentina JemuovićInstructor1 day ago

Assert on the type for behaviour, and the message only when the message itself is part of the contract (e.g. an API error a caller depends on). Over-asserting on free-text messages makes tests brittle. Lock the type; let refactors move the wording.

Module 04

Refactoring under a green bar

Once your test is green, improve the design without changing behaviour — re-running the suite after every small step. We refactor the SHOP checkout into a discount strategy.

Lesson notes

Markdown · Shiki highlighting

The smell: checkout() branches on a customerType string. Replace the conditional with a discount strategy — behaviour identical, tests stay green:

// before — branching on a type flag (the smell)
function discountFor(customer, total) {
  if (customer.type === 'vip')     return total * 0.20;
  if (customer.type === 'staff')   return total * 0.30;
  return 0;
}

// after — a strategy map; open for extension, green throughout
const STRATEGIES = {
  vip:   total => total * 0.20,
  staff: total => total * 0.30,
};
const discountFor = (customer, total) =>
  (STRATEGIES[customer.type] ?? (() => 0))(total);

Run the suite after the extract, then after the inline. Two green bars, one behaviour preserved. Adding a new tier is now a map entry, not a new branch.
